# Inbox Bodyguard: brand & UI system

**Direction: calm, premium, accountable.** Picture a security product that feels like a well-made notebook rather than a hacker terminal. The UI is plain neutral zinc greys (v1.1: white or near-black backgrounds, never tinted) with a single brand colour, **Jade**, used only as an accent. Jade means *guarded / safe*. Red, amber, iris and sky only appear when they carry meaning. A display serif (Instrument Serif) gives the marketing pages a human, editorial voice. The app itself uses Geist for clarity and Geist Mono for evidence, so anything that is *proof* looks like proof.

Files: `tokens.css` (source of truth, generated by `_src/build_tokens.py`), `tokens.json`, `tailwind.config.js`, `components.css` (the `ib-` component classes), `logo/`, `html/` (reference screens), `mockups/` (PNG renders).

## 1. Logo
- **Mark: "sealed flap".** An envelope flap (top) sits over a shield (bottom). A parallel chevron gap separates them, so the envelope's flap line and the shield's top edge are the same line. The mark is two plain filled paths on a 32-unit grid, with no strokes or masks, and it reads at 16px.
- Files: `mark-light.svg` (on light backgrounds: ink flap + Jade 600 shield), `mark-dark.svg` (on dark: ink-50 flap + Jade 400 shield), `mark-mono.svg` (`currentColor`), `lockup-light/dark.svg`, `wordmark-light/dark.svg` (outlined Geist SemiBold, −0.022em), `app-icon-512.svg/.png`, `apple-touch-icon-180.png`, `favicon.svg/.ico/-16/-32/-48.png`.
- Clear space is ½ the mark's height on every side. Minimum size is 16px for the mark and 96px wide for the lockup.
- Don't recolour the two parts independently with arbitrary colours. Don't add outlines. Don't rotate it. Don't put it on Jade backgrounds (use mono white instead).

Rules
1. **Jade is the only brand colour.** It also means "safe". That's deliberate: being protected *is* the brand.
2. **Guard colours belong to the guard.** Never use red for generic errors. System errors (timeouts, network failures) use amber with a cloud-off icon and say "your email is safe".
3. **Every state is shown by shape + icon + label, never colour alone.** Guard states are round pills with a shield icon. Action states are square-cornered pills with a dot (pulsing while pending). Decisions are mono uppercase chips.
4. Iris (approval) is the one colour that asks you to act. Use it sparingly so it keeps pulling attention.

## 4. Space, radius, elevation, motion
- 4px base grid: 2 · 4 · 6 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64 · 80 · 96.
- Radius: xs 4 (chips), sm 6 (small buttons, tags), md 8 (buttons, inputs), lg 12 (cards in lists), xl 16 (primary cards), 2xl 20 (demo window), full.
- Shadows are soft, low-contrast and neutral (`rgba(9,9,11,…)`). Dark mode adds a 1px inner top highlight instead of a heavier shadow.
- Motion: fast 120ms (hover), base 200ms (toggles), slow 320ms (panels, verdict reveal), scan 1400ms. Use `ease-standard` cubic-bezier(.2,0,0,1). `prefers-reduced-motion` sets every duration to 0.
- Focus: a 2px Jade ring with a 2px surface-coloured offset (`--focus-ring`) on every interactive element via `:focus-visible`.

## 5. Voice & tone
Calm, specific and on your side. Think of a good bodyguard: few words, never panicky, always clear about what happened.
- **Say what happened, then what it means for you.** "Blocked a hidden instruction. Nothing was forwarded." Not "⚠️ THREAT DETECTED".
- **Plain verbs, concrete numbers.** "Tried to forward 23 invoices to ap-sync@evil-ledger.example."
- **Attribute every decision.** "Drafted by Reasoning model", "Caught by Guard model · 212 ms".
- **Never blame the user. Never over-claim.** Say "Confidence 0.98", not "100% safe".
- Sentence case everywhere. No exclamation marks in product UI. Use the em dash sparingly.
- Errors fail closed and reassure: "The reasoning model didn't answer in time. Your email is safe and untouched. Nothing was sent."

## 7. The "which model did what" pattern
The aim is that a judge or user can answer "which AI did this?" from **any** surface within one glance.
1. **Four lanes with fixed colours and glyphs.** Guard = Jade + shield. Memory = Sky + brain. Reasoning = Iris + sparkles. Tool/action = Ink + wrench. The same colour, icon and order appear everywhere.
2. **Three levels of detail:**
   - *Inline tag* (`ib-model`): on any AI output, e.g. a draft header shows "Reasoning model" + "Guard ✓".
   - *Mini trail* ("What happened" in the assistant panel): one row per step with lane glyph, plain sentence, latency or decision.
   - *Full evidence* (`evidence.html`): a latency waterfall coloured by lane, then a timeline where each step shows **role · model name · input → output summary · latency · decision**, plus a rail listing each model (ID, calls, time, tokens) and the trust boundary.
3. **Role first, model name second.** UI copy says "Guard model". The specific model (e.g. *Nemotron Safety Guard 8B*) is metadata, so engineers can swap models without a copy change. Model names live in one config map (see handoff).
4. **Guard runs twice:** on the way *in* (scan the email) and on the way *out* (gate every tool call). Show both. The second one is what makes "blocked before any action ran" true.

## 8. Engineer handoff
### Setup
- Import `tokens.css` then `components.css` globally. Use `tailwind.config.js` as your config (it also works with the CDN: load it after `cdn.tailwindcss.com`). Semantic utilities look like `bg-surface`, `text-text-secondary`, `border-border`, `bg-guard-blocked-bg`, `text-model-reason`. Tailwind's `/opacity` modifiers **won't work** on these var-based colours. Use the `-bg`/`-border` tokens instead.
- Theme (v1.1): every page follows the OS by default. Force a theme with `data-theme="light"` or `data-theme="dark"`, or with `class="dark"`, on `<html>`. Every semantic token flips. Use the `.ib-theme-toggle` button with the `ibToggleTheme()` snippet from `_src/partials/head.html`. It saves the choice to `localStorage('ib-theme')`. Run that snippet in `<head>` before first paint to avoid a flash.
- Self-host Geist, Geist Mono and Instrument Serif in production. Fallback stacks are already in the tokens.
- Layout widths: sidebar 232 · list 344 · assistant 352 (`--layout-*`). The reading pane flexes and needs ≥ 480px. Below 1280px, collapse the assistant into a drawer. Below 1024px, drop the sidebar (mobile pattern in `guard.html`).
- Rebuild tokens with `python3 _src/build_tokens.py` and HTML with `python3 _src/build_html.py` (pages + partials). Re-render mockups with `design/_render/render_all.sh`.

### Data each step event should carry (to drive the evidence UI)
`{ run_id, step, lane, role, model_id, title, input_summary, output_summary, latency_ms, decision: "allow"|"deny"|"held"|"info", tokens_in, tokens_out, started_at }`. Stream these over SSE/WebSocket and render rows as they arrive.

### States to build
| State | Pattern (see `components.html`) |
|---|---|
| **Loading** | `ib-skeleton` lines in the reading pane and list. The sidebar guard counter shows "–". Never block the inbox on AI. Show emails first and add badges when they arrive. |
| **Streaming agent steps** | The "What happened" list fills top-down. The current step shows a spinning loader in its lane glyph plus elapsed mono time. Future steps show a dashed empty box. Draft text streams with the `ib-caret` (Iris). Approve stays disabled until the output guard check passes. |
| **Scanning** | `ib-guard--scanning` with `ib-live-dot`. On the landing demo, `ib-scanline` sweeps the email. |
| **Approval needed** | Iris header band + `ib-action--pending`. Actions are **Approve & send (⌘↵)**, Edit, Discard. The sidebar's primary button counts pending drafts ("Review 2 drafts", shortcut A). |
| **Blocked** | List row shows `ib-guard--blocked` and the snippet reads "Quarantined. Content hidden from the assistant." A banner sits at the top of the list and links to the guard result. |
| **Flagged** | Amber pill. The email is readable but the assistant won't act on it until you confirm. |
| **Error** | Amber card with cloud-off icon. Always say what *didn't* happen ("Nothing was sent"), then Retry / View trace. **Fail closed:** if the guard is unavailable, hold the email and run no tools. |
| **Empty** | Dashed card with a Jade shield: "Nothing blocked this week · 412 emails scanned" + **Send a test attack** (this is also onboarding step 3). |

### Landing demo
`landing.html` auto-plays a ~3s state machine: *arrives → guard scans (scanline) → hidden text revealed (switches to "What the AI reads") → blocked verdict*. `?state=blocked` jumps to the end. The "Replay" button restarts it. This is the 30-second aha: hook it to a real `/api/demo/scan` call if time allows, otherwise keep the scripted version.

### Accessibility
Visible focus on everything. Toggles use `role=switch` + `aria-checked`. Segmented controls use `aria-pressed`. Severity always has a text label. Revealed hidden text must be real text, not an image, so screen readers announce it, prefixed with "Hidden from you:". All motion respects reduced-motion.
